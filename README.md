# disorder map
<img width="738" height="68" alt="image" src="https://github.com/user-attachments/assets/dac7cadc-0101-4edc-9a21-e98504a48f7f" />

Интерактивная карта статей и книг по физике неупорядоченных систем — от локализации до случайных матриц. Она помогает проследить путь от статьи к её источникам и найти работы из коллекции, в которых эту статью цитируют.

**[Открыть карту](https://olesyander.github.io/disorder/)**


## Как читать карту

Каждая точка — одна публикация. Нажмите на **название папки**, чтобы увидеть список её работ с авторами. Выберите статью из списка или нажмите на точку — откроется карточка с авторами и аннотацией, а на карте подсветятся её связи. К той же карточке ведёт поиск по названию или автору. Карту можно двигать мышью и масштабировать колёсиком.

Под аннотацией раскройте нужную группу в разделе **Connections**. Название соседней статьи ведёт к её карточке.

| Раздел | Что показывает |
| --- | --- |
| **Cites** | Работы из коллекции, на которые ссылается выбранная статья. В **Citation sources** можно посмотреть, где найдена ссылка, а при наличии данных — страницу и номер записи в библиографии. |
| **Cited by** | Работы из коллекции, которые ссылаются на выбранную статью. |
| **Shared authors** | Публикации с общими авторами и имена этих авторов. |
| **Similar text** | Публикации с близкой лексикой в названиях и аннотациях. В списке указаны совпавшие термины. |

У пары статей может быть несколько связей. Например, если одна цитирует другую и у них похожи аннотации, при выключении **Citations** линия останется благодаря **Similar text**. Флажок **Isolated papers** показывает или скрывает работы без связей при выбранных фильтрах.

## Как из PDF получается граф

1. **Карточки.** После коммита GitHub Actions запускает Python-скрипты. Они извлекают из PDF название, авторов и аннотацию, а для сканов используют распознавание текста. По идентификатору arXiv или DOI сборщик запрашивает запись в arXiv или Crossref. Если идентификатор неизвестен, сборщик сверяет найденные публикации по названию, авторам и доступной аннотации.
2. **Дубликаты.** Контрольная сумма SHA-256 позволяет узнать один и тот же PDF даже после переименования. Разные файлы одной работы сборщик объединяет по идентификаторам или по сочетанию признаков, включая авторов, название и совпадения в тексте. На графе у такой работы одна точка.
3. **Связи.** Сборщик ищет цитирования в библиографиях PDF, в материалах arXiv и в записях Crossref, OpenAlex и Semantic Scholar. При пополнении коллекции он заново сопоставляет сохранённые библиографии с каталогом. Так у новой статьи могут появиться ссылки из ранее загруженных работ. Общих авторов сборщик определяет по идентификаторам и вариантам написания имён. Для текстового сходства сравнивает слова и словосочетания в названиях и аннотациях. Редкие для коллекции термины получают больший вес.
4. **Публикация.** Сборка проверяет, что у каждой связи есть обе карточки, и обновляет в `disorder` файлы [catalog.json](./catalog.json) и [knowledge.json](./knowledge.json). GitHub Pages публикует сайт, а D3 рисует граф в браузере. Ход обновления можно проверить в двух журналах GitHub Actions. [Сборка данных](https://github.com/olesyander/disorder-private/actions/workflows/publish.yml) · [Публикация сайта](https://github.com/olesyander/disorder/actions/workflows/deploy-pages.yml)

Если сборщик нашёл внешний полный текст, карточка ведёт к нему. В остальных случаях сборка может поместить копию PDF в публичную папку `papers/`. У книг из `library/<тема>/Restricted Books/` на карте видна карточка, а исходный PDF остаётся в приватной библиотеке.

## Локальный просмотр

Из корня `disorder` выполните команды для проверки каталога и запуска сайта.

```bash
python3 scripts/validate_site.py --root .
python3 -m http.server 8000
```

Откройте [localhost:8000](http://localhost:8000/). Браузер загружает D3 из CDN.
